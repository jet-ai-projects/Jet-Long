Jet-LongEfficient Long-Context Extension
with Dynamic Bifocal RoPE

Haozhan Tang, Zerui Wang, Yuxian Gu, Song Han, Han Cai

NVIDIANEURIPS 2026

↗ Paper ↗ Code ↗ Hugging Face ▷ Watch the video

A model pretrained with a 32K window has only seen 32K relative positions.
Jet-Long keeps every distant token on one of them,
and its fused kernels run close to FlashAttention speed.

TL;DR

Jet-Long extends a RoPE model past its pretraining window without fine-tuning. Each token sees the 2,048 tokens before it with exact RoPE. Farther tokens share positions in groups of G = ⌈L / 32K⌉, so every distant gap is one the model saw in pretraining, and any input up to 32K runs the unchanged base model. Fused CuTe kernels keep 64K to 128K prefill at 0.83 to 0.88× FlashAttention-3 throughput, and Qwen3-8B decodes slightly faster than with FlashAttention-3.

Why models break past their window

Qwen3-8B-Base was pretrained with a 32K window. At 128K tokens its RULER accuracy falls to 7.7% and its PG-19 perplexity jumps from 9.25 to 79.37. The weights and the text are the same, so how come the model falls apart? Two separate things go wrong.

RoPE runs out of trained angles

RoPE rotates each pair of query and key channels by an angle proportional to position, so attention depends only on the gap between two tokens. Qwen3's 64 pairs per head turn at speeds from 1 radian per token down to about a millionth of a radian. Pretraining gaps never exceed 32,767 tokens: the fastest pair circles 5,215 times in that span, but 24 slow pairs never finish a turn. Pair 48 only ever reaches 59°, and a 128K input pushes it to 237°, angles the model has never seen.

Attention spreads thin

The second failure has nothing to do with positions. Softmax weights sum to one, so every extra token takes a share. If one token scores 9.0 and every other token 0.001, it gets 99.99% of the attention among 2 tokens but only 5.8% among 131,072.

YaRN adds a softmax temperature (logits × 1.30 at 4×), which brings this back to 47% but also changes every short-range score. Jet-Long leaves softmax alone; we think sparse, linear, or hybrid attention is the better fix for thin attention.

Fixed factors trade short inputs for long ones

Zero-shot methods mostly target the first failure. Frequency methods (Position Interpolation, NTK, YaRN) slow the rotations so long gaps land back in the trained angle range. Grouping and chunking methods (Self-Extend, DCA) keep the frequencies and remap position indices. Most fix their factor up front, sized for the longest input, so short inputs pay too: YaRN at 4× nearly doubles Qwen3-1.7B's perplexity at 16K (11.59 → 22.28). Dynamic NTK adapts to the length and spares short inputs, but degrades at long range.

How Jet-Long works

Jet-Long keeps Self-Extend's two windows ("bifocal"). Keys within w0 = 2,048 tokens of the query use normal RoPE; older keys use positions floor-divided by G:

S(q, k) ={ RoPE(xq, q)⊤ RoPE(xk, k)if q − k ≤ w0 RoPE(xq, ⌊q/G⌋)⊤ RoPE(xk, ⌊k/G⌋)otherwise

Grouping only changes position indices. Every token keeps its own key and value.

Pick G from the length

G = max(1, ⌈L / w⌉)

This is the smallest G that keeps every grouped gap inside the pretraining window w. For Qwen3's 32K window, inputs up to 32K get G = 1, which is exactly the base model, and 128K gets G = 4. Nothing is fitted, and w0 is the only hyperparameter.

Keep the cache in base coordinates

G changes during generation (a 98,000-token prompt moves from G = 3 to 4 at token 98,305), so caching grouped keys would mean rewriting the cache. Jet-Long caches keys at their true positions, like the base model. Since RoPE rotations add, it rotates a cached key by Δk = ⌊k/G⌋ − k on the fly, and the query by Δq = ⌊q/G⌋ − q.

Earlier hidden states are not recomputed when G changes, so this only approximates re-running prefill. At a G = 3 → 4 switch on Qwen3-1.7B, the largest logit gap to full re-prefill grows from 0.17 to 0.88, but the greedy next token still matched in every tested step. Across 9,247 RULER generations that cross a switch, scores differ from comparable non-crossing ones by −0.74 points (95% CI −1.83 to +0.35).

Make it fast

FlashAttention applies one set of rotated queries and keys per call, so it can't pick RoPE per query-key pair, and a dense 128K × 128K mask has 17 billion entries. Our reference prefill runs three FlashAttention calls instead:

  1. Alocal window, base RoPE
  2. Ball keys, grouped RoPE
  3. Clocal window, grouped RoPE

B − C leaves the distant keys and A adds the local keys back. With each call's log-sum-exp LSEX and WX = exp(LSEX − M), where M is the largest of the three, the merge is algebraically one softmax:

O =WAOA + WBOB − WCOCWA + WB − WC

This version runs three FlashAttention-2 calls per prefill and re-rotates every distant cached key at each decode step. On Qwen3-8B at 128K it runs prefill at 0.57× and decode at 0.15× FlashAttention-3. Our fused CuTe kernels, built on FlashAttention-4's Hopper code, reduce that overhead. The local band and the distant region don't overlap, so prefill stacks base and grouped Q and K and runs one block-sparse attention call with no subtraction, skipping empty tiles. Decode holds both queries in shared memory and streams over near and distant keys in one kernel.

What we learned

1.Pretraining sees a discrete set of positions

Jet-Long started as a YaRN variant. Our early versions used frequency interpolation in the distant branch, and each needed care to keep angles in range: version 2's continuous stitch at the window edge pushed pair 48's query rotation to 1.81 radians at 128K, past the 1.04 seen in pretraining. Version 6 switched to grouping and became Jet-Long.

We think grouping wins because pretraining gaps are whole numbers. Each gap from 0 to 32,767 is one combination of 64 angles, so pretraining shows the model 32,768 positional patterns, not a continuum. YaRN at 4× produces mixes it never saw: for a key 100,001 tokens back, the fast pairs rotate as if the gap were 100,001 and the slow pairs as if it were about 25,000. Grouping with G = 4 maps that key to 25,000 or 25,001 on every pair at once.

In the same two-window design on Qwen3-1.7B, grouping beats frequency interpolation by 6.99 RULER points at 64K and 4.30 at 128K. Interpolation still wins a few tasks, such as MK-NIAH-2 at 128K (33.0 vs. 24.0); we suspect grouping costs resolution, since tokens in one group look equally far away.

2.Compress only as much as the length needs

A fixed factor sized for the longest input taxes every shorter one. Picking G from the length avoids that: Jet-Long's PG-19 perplexity from 4K to 32K matches the base model exactly on all three Qwen3 sizes. On Llama-3-8B (8K window), Self-Extend set up for 128K loses 3.8 to 4.9 RULER points at 4K, while Jet-Long stays within 0.21.

3.Keep nearby tokens exact

Without the local window (w0 = 0), RULER at 64K to 128K collapses to 1 to 5%: with G = 2 to 4, the last few tokens share positions, so their order is lost. Any w0 from 512 to 4,096 lands within 2 points of the best, so 2,048 is the default.

4.Pick an algorithm the kernel can fuse

Three properties make fusion possible: the correction Δk = ⌊k/G⌋ − k depends only on a key's index and G, base-coordinate caching keeps one cache that is never rewritten, and the local and distant regions don't overlap, so one block-sparse launch covers both. Against the same CuTe kernel without two windows, the bifocal rule costs 7 to 12% of prefill throughput at 64K to 128K, and Qwen3-8B decode runs at 0.99 to 1.03× that kernel.

5.What it doesn't fix

Jet-Long fixes positions only. Attention still thins out, prefill is still quadratic, and the KV cache still grows with length. To resolve the efficiency bottleneck of agentic and long-context workloads, check out our latest work, Jet-QSparse.

Results

We extend Qwen3-1.7B, 4B and 8B Base from 32K to 128K and compare with Dynamic NTK, YaRN, DCA and Self-Extend on RULER, HELMET-RAG and PG-19. RULER and PG-19 are averaged over six lengths from 4K to 128K (PG-19 as a geometric mean).

Jet-Long leads RULER by 4.79, 2.18 and 2.03 points at 1.7B, 4B and 8B and has the lowest PG-19 perplexity at every size; at 128K it stays at 11.41, 9.62 and 8.51 while the base models reach 71.00, 104.66 and 79.37. On HELMET-RAG it leads at 4B and 8B, and Self-Extend leads at 1.7B by 0.73.

Speed

On one H100 with CUDA graphs, fused prefill at 64K to 128K reaches 0.83 to 0.88× FlashAttention-3 throughput across the three Qwen3 sizes, or 0.88 to 0.93× a matched CuTe kernel without the two windows. At batch size 1, Qwen3-8B decodes at 1.04 to 1.08× FlashAttention-3, within 3.6% of FlashAttention-2, the fastest decode reference.

Try it

Jet-Long is training-free and Apache 2.0. Each variant reuses the original Qwen3 weights with a new config and modeling file, so loading is a normal from_pretrained call.

git clone https://github.com/jet-ai-projects/Jet-Long.git && cd Jet-Long
pip install -e .                  # then flash-attn 2.8.3, see the README
bash scripts/model/setup_model_variants.sh
from transformers import AutoModelForCausalLM, AutoTokenizer

path = "model_cache/Qwen3-8B-Base-jetlong"
model = AutoModelForCausalLM.from_pretrained(
    path,
    trust_remote_code=True,
    attn_implementation="flash_attention_2",
    torch_dtype="bfloat16",
    device_map="cuda",
)
tokenizer = AutoTokenizer.from_pretrained(path)

The fused variant (jetlong_fused) needs an SM90 GPU (H100) and FlashAttention-4 in a separate environment, and loads with attn_implementation="sdpa". The README covers setup, the RULER, PG-19 and HELMET-RAG scripts, and throughput benchmarks against FlashAttention-2.
